# Active-time Web preparation deadline

True Web metadata now opens a separate default five-minute noninteractive budget through profile input, free-port work, initial certificate checking and post-trust verification. It uses injected webPreparationTimeoutMs with the existing monotonic clock and scheduler. The explicit onNonInteractive Boolean protocol pauses one continuous consent/trust interval, then resumes only the remaining budget before verification. Human progress labels do not decide budget policy.

Consumed active time is checked before pausing; an overdue certificate check cannot escape the budget by opening consent. Epochs reject stale callbacks from earlier segments, duplicate transitions are idempotent and early callbacks rearm the remaining time. The existing per-call runProcess timeout still runs during OS trust even while this shared active-time budget is paused.

Normal provider completion receives a post-check and permanently closes this budget before environment validation, later logging or debugger handoff. An original fatal prepareWebLaunch rejection keeps priority unless an actual timeout/abort already selected another outcome. Checks occur at runtime provider-reply, interaction-transition and runDotnet checkpoints. When timer delivery is delayed, not every internal filesystem/network dispatch is elapsed-time-prechecked; the normal-reply check preserves outcome/handoff safety. This is not OS preemption or a hard whole-phase bound.

The existing Promise.all input-read policy remains unchanged. An early passive-input failure can finish logical preparation while a pure sibling read stays observed; actual drain of every filesystem request is not guaranteed. If both noncooperative reads remain pending, the helper/workflow, source gate and owned output stay held until settlement. This does not authorize abandoning write-capable providers. Port-close, direct-process, session and disposal ownership retain their existing actual-settlement rules. Save, SDK and owned-handoff budgets remain separate.
