It verifies identity, original entry, command/binding, exact module bytes, and unchanged native debugger payload. To rerun an editor test, use a disposable extraction of a matching variant, apply `overlay.install_file_app_support` and save its updated package manifest, and copy this test/fixture into a writable work directory. Copy `project-launch.json` to the fixture's `.vscode/launch.json`, and build `workspace/project/Regression.csproj` into `workspace/project/output` using the pinned SDK. The supplied project launch selects ARM64 for this observed host; adjust it for another host. Pass the test script via the editor's `--extensionTestsPath`. Use the extracted extension as `--extensionDevelopmentPath`, an isolated user-data/extensions directory, the matching SDK root, and disabled automatic updates. The test depends on the extension's normal runtime-acquisition dependencies; it is not a substitute for building the complete variant. Run background editor tests in a hidden window. The normal source-level tests and current release packaging path are documented in the behavior guide.

Local paths in copied results/traces are normalized as `<f5-work>`, `<workspace>`, `<dotnet-root>`, and `<user-profile>`. The debugger, editor archive, VSIX, SDK caches, and build outputs are not committed here.
